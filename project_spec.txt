PROJECT OVERVIEW

Project Title: Lost & Found Management System for College
Tech Stack: MERN (MongoDB, Express, React, Node.js) + Vite (client)

The Lost & Found Management System is a web-based application to help students/staff report lost items, record found items, browse/search all reports, and manage physical handover through Security and Admin workflows.

PROBLEM STATEMENT

In a college campus, students often lose personal items such as ID cards, books, wallets, mobile phones, and accessories. Notice boards and word-of-mouth are inefficient and unreliable. A digital system is needed to track item reports, status changes, and basic claim handling.

SOLUTION (AS IMPLEMENTED)

- Users can report lost items and found items (single “Item” model with a “type” field).
- All roles can browse items, view details, and filter by type/status/category/search.
- Users can view “My Reports” (items they created) and can submit a claim request on found items.
- Security Officers can add found items from the security desk and update status to reflect physical handling (At Security / Returned).
- Admin can manage users (roles) and remove fake/duplicate records.
- UI is styled with a Material 3 theme and uses role-based layouts (no emoji icons).

USER ROLES & PERMISSIONS

A. User (Student / Staff)
- Can register and login.
- Can report lost items and found items.
- Can browse all items and view item details.
- Can view “My Reports” (only their own reported items).
- Can submit a claim request on a found item.

B. Security Officer (Campus Security Staff)
Role Description:
Manages items physically submitted/collected at the security office and keeps item status aligned with real-world handling.

Permissions:
- Can login to Security dashboard.
- Can add found items received at the security desk.
- Can view items and update item status (e.g., At Security, Returned).

Restrictions:
- Cannot manage user roles.
- Cannot delete users.
- Cannot permanently remove system records.

C. Admin (College Authority)
- Can login to Admin dashboard.
- Can view items and update item statuses.
- Can remove fake/duplicate item reports (delete item records).
- Can manage users and assign roles (user/security/admin).

DATABASE STRUCTURE (Schemas – Current Shape)

A. User
- name: String
- email: String (unique)
- password: String (hashed)
- role: String ('user' | 'security' | 'admin')

B. Item (single collection for both “lost” and “found”)
- title: String
- description: String
- category: String
- location: String
- date: Date
- imageUrl: String (if provided)
- type: String ('lost' | 'found')
- status: String ('Lost' | 'Found' | 'At Security' | 'Returned')
- userId: ObjectId (ref User)  // reporter/creator

Claim-related fields (used for found items / claim flow):
- claimedBy: ObjectId (ref User, optional)
- claimStatus: String ('Pending' | 'Approved' | 'Rejected', optional)

FEATURE WORKFLOW (IMPLEMENTED)

1) Report an item (User)
- User submits a lost/found report.
- Item is saved with type = lost/found and a status (commonly 'Lost' for lost reports and 'Found' for found reports).

2) Browse & search (All)
- Users can browse all items and use filters/search.

3) “My Reports” (User)
- Users can view items they personally reported (server-side filtered via a dedicated endpoint).

4) Claim a found item (User)
- User submits a claim request on a found item.
- Item shows claim state on the detail page (e.g., pending/claimed).

5) Physical handling (Security)
- Security adds found items received at the desk.
- Security updates status to 'At Security' when held at the desk and 'Returned' when handed over.

6) Oversight (Admin)
- Admin can update statuses, remove invalid entries, and manage user roles.

FRONTEND ROUTES (React Router v6)

Public:
- /                     Home (index route)
- /items                Items list
- /items/:id            Item detail
- /login                Login
- /register             Register

Protected (requires login):
- /report-lost          Report lost item
- /report-found         Report found item
- /my-reports           My reports

Role-protected:
- /admin                Admin dashboard (admin only)
- /admin/users          User management (admin only)
- /security             Security dashboard (security only)
- /security/add-found   Add found item (security only)

UI / THEMING NOTES (Current)

- Material 3 design tokens are used for consistent styling across pages and navigation.
- Role-based layout selection ensures Admin/Security always see their own navigation across the app.
- Emoji icons were removed for a professional UI.

API ENDPOINTS (SERVER)

Auth:
- POST /api/auth/register
- POST /api/auth/login

Items:
- GET  /api/items                 (public) list items (supports filters via query params)
- GET  /api/items/:id             (public) get item detail
- POST /api/items                 (auth) create item (lost or found)
- GET  /api/items/my-reports      (auth) list items reported by the logged-in user only
- POST /api/items/:id/claim       (auth) submit claim request for a found item
- PUT  /api/items/:id/status      (admin or security) update item status
- DELETE /api/items/:id           (admin) delete item

Users (Admin):
- GET  /api/users
- PUT  /api/users/:id/role
